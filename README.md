# LLM-Desc: LLM-Derived Activity Descriptors for Process Variant Clustering

Replication code for the paper

> Mohammadreza Fani Sani and Michal Rosik. *Do LLM-Derived Activity Descriptors Help Process Variant Clustering? A Controlled Multi-Log Study.* Submitted to GenAI4PM 2027.

The paper asks whether describing each activity label with a large language model (LLM) and embedding those descriptions gives better process variant clusters than embedding the raw labels, a learned activity2vec embedding, or a structural n-gram baseline. This repository contains the code, prompts, schemas, configurations, preregistrations, tests and the frozen GPT-4.1 activity descriptors needed to rerun every experiment from the public event logs. It contains no event logs, no embeddings and no result files; every result is regenerated by the commands below.

**Naming.** The representation called **LLM-Desc** in the paper is called **P7** (`p7`) in the code, the configuration files and the output file names. The internal name is kept so that the frozen prompt bundle and its hashes stay valid.

## Contents

| Path | Contents |
|---|---|
| `src/llm_variant_clustering/` | Library: variant extraction, LLM providers and response cache, descriptor compilation, embeddings, weighted k-means and automatic K, process discovery and replay metrics, bootstrap utilities |
| `scripts/` | One command-line entry point per experiment (listed in [Pipeline](#pipeline)) |
| `configs/prompts/`, `configs/schemas/` | Prompt templates and JSON schemas |

| `configs/clustering/dynamic_k_v1.json` | Frozen automatic-K configuration |
| `frozen_descriptors/` | The GPT-4.1 activity descriptors used in the paper (one JSON record per activity label, 8 files, about 70 KB), with SHA-256 values; see [step 2](#2-llm-desc-activity-descriptors-sect-3) |
| `evaluation/<study>/PRESPEC.md` | Preregistrations of the supplementary studies, written before their results; see [`evaluation/README.md`](evaluation/README.md) |

| `models/` | Empty; the Hugging Face model cache goes here |

## Requirements

- Python 3.11, 3.12 or 3.13. The reported results were produced with Python 3.12.8 on Windows, CPU only.
- Azure OpenAI access is optional. The GPT-4.1 descriptors behind the paper are included, so clustering, replay and all baselines run offline. Azure is needed only to regenerate the descriptors and for the LLM robustness and cluster-naming studies of Sects. 5.4 and 6.
- Optional: further Azure OpenAI deployments for the robustness studies of Sect. 6, and a separate Python 3.9 environment for the semantic tagger comparator (see [Optional components](#optional-components)).

## Setup

PowerShell on Windows (use `source .venv/bin/activate` and `:` instead of `;` in `PYTHONPATH` on Linux and macOS):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.lock.txt
pip install -e ".[dev,embeddings,azure]"

# Run every command from the repository root with these settings.
$env:PYTHONPATH = "src;scripts"
$env:PYTHONHASHSEED = "0"      # PM4Py discovery depends on set iteration order
$env:OMP_NUM_THREADS = "2"
```

`requirements.lock.txt` pins the exact package versions of the original runs. `pyproject.toml` gives the looser ranges the code is expected to work with.

### Embedding model

All embeddings use `BAAI/bge-large-en-v1.5` at revision `d4aa6901d3a41ba39fb536a557fa166f842b0e09`. Download it once into `models/huggingface`:

```powershell
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-large-en-v1.5', revision='d4aa6901d3a41ba39fb536a557fa166f842b0e09', cache_folder='models/huggingface')"
$env:HF_HUB_OFFLINE = "1"      # afterwards, keep runs offline and pinned
```

### Azure OpenAI

The code authenticates with Microsoft Entra ID through the Azure CLI; no API key is read or stored.

```powershell
az login
$env:AZURE_OPENAI_ENDPOINT = "https://<your-resource>.openai.azure.com/"
# Optional second resource for deepseek-v4-pro and gpt-4o (falls back to the first):
$env:AZURE_OPENAI_ENDPOINT_SECONDARY = "https://<other-resource>.openai.azure.com/"
```

`.env.example` lists every environment variable the code reads. LLM responses are cached on disk by request hash, so reruns do not repeat calls. Regenerating all descriptors takes 829 short GPT-4.1 calls: 548 activity labels of the seven logs plus 281 English BPI 2015 names.

### Tests

```powershell
python -m pytest -q
```

Expected on a fresh checkout: 169 passed and 6 skipped. One cluster-naming test needs the BGE model in `models/huggingface`, or network access. The 6 skipped tests check generated outputs and run once the corresponding pipeline stage has been executed.

## Pipeline

Stages are listed in dependency order. Every script prints `--help`. Outputs go to `evaluation/` and `datasets/interim/`, which are ignored by `.gitignore`.

### 1. Calibration split (Sect. 4)

BPI 2020 is the development log. For BPI 2017 and BPI 2019, 45 variants are reserved for calibration and excluded from evaluation:

```powershell
python scripts/create_calibration_split.py datasets/processed/bpi2017/variants.parquet evaluation/cross_dataset_tuning/bpi2017 --seed dynamic-calibration-bpi2017-v1 --sample-size 45
python scripts/create_calibration_split.py datasets/processed/bpi2019/variants.parquet evaluation/cross_dataset_tuning/bpi2019 --seed dynamic-calibration-bpi2019-v1 --sample-size 45
```

The evaluation variants are then `evaluation/cross_dataset_tuning/<log>/reserved_evaluation.parquet` (5,578 for BPI 2017 and 11,928 for BPI 2019). For Sepsis and RTFM use `datasets/processed/<log>/variants.parquet`.

### 2. LLM-Desc activity descriptors (Sect. 3)

Each distinct activity label is described once by GPT-4.1 with the frozen prompt. For example, `Declaration APPROVED by ADMINISTRATION` becomes `action: approve; business_object: declaration; process_stage: decision; explicit_state: approved; explicit_role: administration`.

**Option A (recommended, exact reproduction).** Restore the descriptors used in the paper:

```powershell
python scripts/restore_frozen_descriptors.py
```

This checks each file in `frozen_descriptors/` against `SHA256SUMS` and copies it to the path the pipeline reads, including those of the BPI 2012 and BPI 2015 studies of step 7. You can then skip this step and the `normalize` stages of `run_supp_extra_logs.py` and `run_supp_bpi2015_english.py`. The BPI 2020 file matches the hash recorded in `configs/frozen/p7_representation_v1/manifest.json`.

**Option B (regenerate with Azure OpenAI).**

```powershell
$P = "configs/frozen/p7_activity_gpt41_v1"
python scripts/run_p7_activity_normalization.py <variants.parquet> evaluation/full_benchmark/<log>/activity_semantics_frozen.parquet `
    --cache-dir datasets/interim/llm_cache --endpoint $env:AZURE_OPENAI_ENDPOINT `
    --deployment gpt-4.1 --model-version 2025-04-14 --prompt $P/prompt.txt --schema $P/schema.json
```

Use `<log>` in `bpi2017`, `bpi2019`, `sepsis`, `rtfm`. For BPI 2020 write to `evaluation/p7_recovery/all_activity_semantics_frozen.parquet`. Temperature is 0, but GPT-4.1 is not bit-for-bit deterministic, so a fresh run can differ in a few descriptor fields from the files in `frozen_descriptors/`; Sect. 6 reports how much this matters (normalizer substitution).

### 3. Clustering at automatic K (Table 1, Sect. 5)

```powershell

    evaluation/p7_recovery/all_activity_semantics_frozen.parquet evaluation/raw_embedding_baseline/bpi2020 `
```

The selected K values are BPI 2020 9, BPI 2017 2, BPI 2019 6 and RTFM 2. On Sepsis no K meets the selector constraints, and K = 8 is used as the fallback.

## Changes relative to the original scripts

The code is the code that produced the paper, with these changes for release:

1. Azure endpoints are read from `AZURE_OPENAI_ENDPOINT` and `AZURE_OPENAI_ENDPOINT_SECONDARY` instead of being written in the scripts.
2. Internal endpoint host names were removed from two preregistrations. Their original SHA-256 values are listed in [`evaluation/README.md`](evaluation/README.md).
3. `scripts/make_matched_k_ngram.py` is new. In the original study the matched-K n-gram partitions of Table 3 were written by a separate supplementary study that is not part of the paper. The helper recomputes them with the same calls and seeds; its output is byte-identical to the original partitions on all five logs.
4. `run_replay_matched_k.py summarize` reads a cross-check column from that same supplementary study and leaves it empty when the file is absent.
5. `scripts/restore_frozen_descriptors.py` is new. It copies the shipped descriptors to their original paths.

## Determinism

Weighted k-means uses fixed seeds (17, 29, 43, 59, 71; 10 initializations each). Splits are derived from SHA-256 hashes of variant identifiers. PM4Py's inductive miner depends on Python's hash seed, so set `PYTHONHASHSEED=0` to reproduce the frozen replay values; Sect. 6 reports the spread over 10 hash seeds. GPT-4.1 output at temperature 0 is close to, but not exactly, deterministic; use the shipped descriptors (step 2, option A) for exact reproduction.
